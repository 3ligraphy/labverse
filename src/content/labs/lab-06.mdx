export const SQLITE_CODE = `import * as SQLite from 'expo-sqlite';

export const dbPromise = SQLite.openDatabaseAsync('tasks.db');

export async function setup() {
  const db = await dbPromise;
  await db.execAsync(\`
    PRAGMA journal_mode = WAL;
    CREATE TABLE IF NOT EXISTS tasks (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      title TEXT NOT NULL,
      done INTEGER NOT NULL DEFAULT 0
    );
  \`);
}

export async function addTask(title: string) {
  const db = await dbPromise;
  const result = await db.runAsync('INSERT INTO tasks (title) VALUES (?)', title);
  return result.lastInsertRowId;
}

export async function getOpenTasks() {
  const db = await dbPromise;
  return db.getAllAsync('SELECT * FROM tasks WHERE done = ? ORDER BY id DESC', 0);
}

export async function addMany(titles: string[]) {
  const db = await dbPromise;
  await db.withTransactionAsync(async () => {
    for (const title of titles) {
      await db.runAsync('INSERT INTO tasks (title) VALUES (?)', title);
    }
  });
}`;

export const SUPABASE_CODE = `import 'react-native-url-polyfill/auto';
import { createClient } from '@supabase/supabase-js';
import 'expo-sqlite/localStorage/install';

const supabaseUrl = process.env.EXPO_PUBLIC_SUPABASE_URL!;
const supabasePublishableKey = process.env.EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY!;

export const supabase = createClient(supabaseUrl, supabasePublishableKey, {
  auth: {
    storage: localStorage,
    autoRefreshToken: true,
    persistSession: true,
    detectSessionInUrl: false,
  },
});`;

export const LARGE_SECURE_CODE = `class LargeSecureStore {
  private async _encrypt(key: string, value: string) {
    const encryptionKey = crypto.getRandomValues(new Uint8Array(256 / 8));
    const cipher = new aesjs.ModeOfOperation.ctr(encryptionKey, new aesjs.Counter(1));
    const encryptedBytes = cipher.encrypt(aesjs.utils.utf8.toBytes(value));
    await SecureStore.setItemAsync(key, aesjs.utils.hex.fromBytes(encryptionKey));
    return aesjs.utils.hex.fromBytes(encryptedBytes);
  }

  async setItem(key: string, value: string) {
    const encrypted = await this._encrypt(key, value);
    await AsyncStorage.setItem(key, encrypted);
  }

  async getItem(key: string) {
    const encrypted = await AsyncStorage.getItem(key);
    if (!encrypted) return encrypted;
    return this._decrypt(key, encrypted); // reads the key from SecureStore
  }
}`;

export const SYNC_CODE = `export async function syncPending() {
  const db = await dbPromise;
  const waiting = await db.getAllAsync('SELECT * FROM tasks WHERE synced = 0');
  if (waiting.length === 0) return 0;

  const { error } = await supabase
    .from('tasks')
    .upsert(waiting.map((t) => ({ id: t.id, title: t.title, done: t.done === 1 })), { onConflict: 'id' });
  if (error) throw error;

  for (const t of waiting) {
    await db.runAsync('UPDATE tasks SET synced = 1 WHERE id = ?', t.id);
  }
  return waiting.length;
}`;

Two more words you will meet in every part:

- **Synchronous** means the answer comes back at once (MMKV). **Asynchronous** means the answer comes later, so you write `await` (AsyncStorage, SQLite, SecureStore, Supabase).
- Storage keeps **text**, not JavaScript objects. **Serialize** = turn an object into text with `JSON.stringify`. **Deserialize** = turn the text back into an object with `JSON.parse`.

<Part n="2" title="Key-value storage: AsyncStorage and MMKV" time="30 min" />

**AsyncStorage** saves text under a key, on the phone. It exists because React Native has no built-in way to keep small data between launches. It is asynchronous (every call needs `await`), it is not encrypted, and it is included in **Expo Go**.

<Terminal title="Terminal — install" lines={['$ npx expo install @react-native-async-storage/async-storage']} />

```ts
import AsyncStorage from '@react-native-async-storage/async-storage';

await AsyncStorage.setItem('settings', JSON.stringify({ dark: true, size: 18 })); // save (object → text)
const text = await AsyncStorage.getItem('settings');           // read: the text, or null
const settings = text ? JSON.parse(text) : null;                // text → object
await AsyncStorage.mergeItem('settings', JSON.stringify({ size: 20 })); // update one field
await AsyncStorage.removeItem('settings');                      // remove one key
await AsyncStorage.clear();                                     // remove every key of this app
const keys = await AsyncStorage.getAllKeys();                   // which keys exist
```

<KvFlow />

Reading and saving can fail (a full disk, a broken value), so put them in `try / catch`:

```ts
try {
  const text = await AsyncStorage.getItem('settings');
  if (text) setSettings(JSON.parse(text)); // JSON.parse throws if the text is broken
} catch (error) {
  console.warn('Could not load the settings', error); // the app keeps its defaults
}
```

<Part n="3" title="A database on the phone: SQLite" time="27 min" />

A **database** keeps data in **tables**. A table has **columns** (the fields, each with a type) and **rows** (one row per thing, for example one task). The **primary key** is a column whose value is different in every row, usually `id`, so one row can always be found.

Key-value storage is not enough when the data is a list you search. To show “tasks not done, newest first” with AsyncStorage you would load the whole list, `JSON.parse` it, filter and sort it in JavaScript, and save the whole list again after every change. A database does it with one query, and changes one row at a time.

**SQLite** is a database in one file on the phone. You talk to it with **SQL**, a language of short statements:

<Part n="4" title="Secrets: secure storage" time="20 min" />

**Sensitive data** is data that lets someone act as the user or harms them if it leaks: tokens, keys, personal information. When a user signs in, the server gives the app tokens:

<Cards cols={2} items={[
  { tag: 'short-lived', icon: 'key', title: 'Access token', text: 'Proof of who the user is, sent with every request. It stops working after a short time (Supabase: about 1 hour).' },
  { tag: 'long-lived', icon: 'key', title: 'Refresh token', text: 'Used to get a new access token without asking for the password again. Whoever has it can stay signed in as the user.' },

AsyncStorage keeps them as plain text. **Encryption at rest** means the data is stored encrypted, so the file is unreadable without a key. On iOS the **Keychain**, and on Android the **Keystore**, keep that key inside the phone’s secure hardware. **Expo SecureStore** uses them for you.

### B. Rows: select, insert, update, delete

Every call returns `{ data, error }`. Check `error` first.

```ts
// read: an array of rows (filters and order are optional)
const { data, error } = await supabase.from('tasks').select('*').eq('done', false).order('created_at');

// add: no rows come back unless you chain .select()
const { error: addError } = await supabase.from('tasks').insert({ title: 'Buy milk' });
const { data: created } = await supabase.from('tasks').insert({ title: 'Read' }).select().single();

// change and remove: always with a filter, so only the rows you mean change
await supabase.from('tasks').update({ done: true }).eq('id', task.id);
await supabase.from('tasks').delete().eq('id', task.id);

if (error) console.warn(error.code, error.message); // e.g. 42501 = blocked by Row Level Security
```

### C. Auth: users and sessions

**Supabase Auth** checks the email and password and answers with a **session**: the access token and the refresh token. supabase-js keeps the session in `auth.storage` (so the user stays signed in after a restart) and sends the access token with every request.

```ts
await supabase.auth.signUp({ email, password });                 // new account
const { data, error } = await supabase.auth.signInWithPassword({ email, password });
const { data: { session } } = await supabase.auth.getSession();  // the saved session, or null
const { data: listener } = supabase.auth.onAuthStateChange((event, session) => {
  // SIGNED_IN, SIGNED_OUT, TOKEN_REFRESHED…: update the screen
});
listener.subscription.unsubscribe(); // in the useEffect cleanup
await supabase.auth.signOut();
```

### D. Row Level Security

The publishable key is inside every copy of your app, so anyone can call your project’s API. **Row Level Security (RLS)** makes the **database** decide, for every row and every request, what this user may do. Checks in your app’s code are not enough: anyone can send requests without your app.

```sql
alter table public.tasks enable row level security; -- now nothing is allowed…

create policy "Users read their own tasks" on public.tasks   -- …until a policy allows it
  for select to authenticated
  using ( (select auth.uid()) = user_id );

create policy "Users add their own tasks" on public.tasks
  for insert to authenticated
  with check ( (select auth.uid()) = user_id );
-- the same for update (using + with check) and delete (using)
```

<Explain parts={[['for select', 'the operation it allows'], ['to authenticated', 'only signed-in users'], ['using ( … )', 'checked for every existing row: which rows they may see or change'], ['with check ( … )', 'checked for every new or changed row: may it be saved?'], ['(select auth.uid())', 'the id of the user who sent the request']]} />

### E. Storage: files in buckets

A **bucket** is a folder for files. A **public** bucket gives each file a fixed URL anyone can open: right for profile photos. A **private** bucket gives **signed URLs** that stop working after the number of seconds you choose: right for personal documents. Storage has its own policies; a common rule is “each user writes only in the folder named after their id”.

```ts
import { decode } from 'base64-arraybuffer';

// the picker gives the photo as base64 text (base64: true); Storage wants bytes
const result = await ImagePicker.launchImageLibraryAsync({ mediaTypes: ['images'], base64: true });
const photo = result.assets![0];
const path = userId + '/avatar.png';

const { error } = await supabase.storage
  .from('avatars')
  .upload(path, decode(photo.base64!), { contentType: 'image/png', upsert: true });

const { data } = supabase.storage.from('avatars').getPublicUrl(path);   // public bucket
const { data: signed } = await supabase.storage.from('documents').createSignedUrl(path, 60); // private, 60 s
await supabase.storage.from('avatars').remove([path]);
```

Real apps use both: the **phone** for speed and for working offline, the **cloud** for sharing and for keeping data safe when a phone is lost.

<Cards cols={2} items={[
  { tag: 'cloud-first', title: 'Cloud-first', text: 'Send to the server, show the result when it answers. Simple, but nothing works without a connection.' },
  { tag: 'local-first', title: 'Local-first', text: 'Save on the phone and show it at once; send to the server later. Works offline. This part builds a simple version.' },

The plan for each new or changed task:

1. Save it in SQLite with a column **synced = 0**: it is a **pending operation**, waiting to be sent.
2. **NetInfo** tells the app whether the phone is online, and when the connection comes back.
3. When online: send every row with `synced = 0`. If the request **fails**, they stay `synced = 0` and are sent next time (a **retry**).
4. Only after Supabase answered without an error: `synced = 1`.

<Terminal title="Terminal — install" lines={['$ npx expo install @react-native-community/netinfo', '# included in Expo Go']} />

```ts
import NetInfo from '@react-native-community/netinfo';

const state = await NetInfo.fetch();                 // once: state.isConnected
const unsubscribe = NetInfo.addEventListener((state) => {
  if (state.isConnected) syncPending();              // the connection is back: send what waits
});
// const net = useNetInfo();                         // or as a hook inside a component
```

**Duplicates.** Sometimes the server saves the row but its answer never reaches the phone. The phone thinks it failed and sends the task again. With `insert`, the cloud now has the task **twice**. The fix: the phone gives each task its **own id** (`Crypto.randomUUID()`), and sends with `upsert` on that id — the second send updates the same row.

**Conflicts.** If the same task is changed on two phones while both are offline, the last one to sync wins (the final project keeps an `updated_at` time for this). Apps that must not lose any change merge them or ask the user — that is a full **sync engine**, and it is beyond this lab. What you build here is the base those engines start from.
