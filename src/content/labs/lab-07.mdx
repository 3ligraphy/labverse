Words used in every part:

- **Hardware** — the physical parts of the phone: the camera, the vibration motor, the screen.
- **Permission** — the user’s answer (yes or no) to “may this app use the camera?”. Phones ask once per app.
- **Haptics** — short vibrations that tell the user something happened, like a tap on the finger.
- **Test** — code that runs a part of your app and checks the result. It says **PASS** or **FAIL**.
- **Build** — turning your project into an app file a phone can install (an **APK** on Android).
- **Native code** — the Kotlin (Android) or Swift (iPhone) code inside the phone app. Your code is **JavaScript**; packages like `expo-camera` bring the native code that talks to the camera.

### D · Haptics: feedback you feel

`expo-haptics` plays short vibrations. There are three kinds of call:

<Cards cols={3} items={[
  { tag: 'an outcome', title: 'notificationAsync(type)', text: '`Success`, `Warning` or `Error`: three different patterns. Smart QR uses Success and Error.' },
  { tag: 'a choice', title: 'selectionAsync()', text: 'The lightest tap: a choice changed. Smart QR uses it for **Flip camera**.' },
  { tag: 'a touch', title: 'impactAsync(style)', text: 'Like two objects touching: `Light`, `Medium`, `Heavy`, `Rigid` or `Soft`.' },
]} />

Two rules from Expo’s documentation shape Smart QR:

- **iPhones play no haptics while the camera is active** (and none in Low Power Mode). So Smart QR vibrates on the **result card**, after the camera closed.
- On Android, the vibration permission is added for you. Phones without a vibration motor throw an error, so every call is inside `try / catch`.

A **test** is code that runs part of your app and checks the result with an **assertion** (“I expect this to equal that”). When you change the app later, the tests run again in seconds and tell you if something that worked is now broken — a **regression**.

<Part n="8" title="Deployment: EAS Build, Submit, Update" time="12 min" />

Expo Go runs your project only while your PC serves it. To give the app to others you need a **build**: the app file itself. **EAS** (Expo Application Services) does the work on Expo’s servers.

Words for this part:

- **Binary** — the installed app file: an **APK** (Android, installs with a tap), an **AAB** (Android App Bundle, the format Google Play wants) or an **IPA** (iPhone).
- **Signing** — a digital signature that proves who made the app. Android uses a **keystore** (a file with your key). Every update must be signed with the same key.
- **Profile** — a named set of build settings in `eas.json`: development, preview, production.
- **Internal distribution** — sharing a build with a link instead of a store.
- **Update** — new JavaScript sent to apps already installed (“over the air”), without a new binary.

### Acceptance criteria

Your Smart QR is complete when:

- [ ] Start scanning shows “Checking camera permission…”, then asks; **Don’t allow** twice shows **Open settings**
- [ ] One QR code gives **one** result (one `Scanned:` line) and **one** vibration
- [ ] A good code plays the Success vibration, an empty code the Error vibration
- [ ] **Flip camera** switches the camera with a small tap
- [ ] A Wi-Fi code shows the network name and never the password
- [ ] **Run tests** passes: 8 unit tests and 5 component tests, each new one failing on the bug it was written for
- [ ] **Run flow** passes: the Maestro flow reaches the result card
- [ ] `app.json` has your own id and `eas.json` makes a preview APK
