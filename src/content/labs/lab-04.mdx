### Rewind: Stack vs Tabs, with an example

Labs 2 and 3 already covered this — here's the short version, with the exact example this lab uses.

<Cards cols={2} items={[
  { icon: 'branch', title: 'Stack', text: 'Screens pile up, like a deck of cards. Opening a new one **pushes** it on top; the back button **pops** it off. There is history: Home → Details → (back) → Home.' },
  { icon: 'grid', title: 'Tabs', text: 'Screens sit **side by side**. Switching tabs doesn\'t push anything — there is no "back" to a tab, each one just keeps its own state while hidden.' },
]} />

**The example this app uses:** tapping a product card is a **Stack** push (Shop → Details, with a back arrow); switching between Shop / Cart / Profile is **Tabs** (no history, no back arrow, instant switch).

<FileTree title="Who owns which navigator" lines={[
  'app/',
  '  _layout.tsx # <Stack> — Shop/Cart/Profile vs Details *',
  '  (tabs)/',
  '    _layout.tsx # <Tabs> — Shop vs Cart vs Profile *',
  '    index.tsx',
  '    cart.tsx',
  '    profile.tsx',
  '  product/',
  '    [id].tsx # pushed on top of the Stack, never a tab',
]} />

```tsx title="the example: tapping a product card"
// inside ProductCard.tsx — this is a Stack push, not a tab switch
onPress={() => router.push(`/product/${product.id}`)}
```

Notice the **Tabs navigator is nested inside the Stack**, as one of its screens (`name="(tabs)"`). That's why switching tabs never shows a back arrow — you're moving sideways inside one Stack screen — but tapping a product does, because it pushes a brand new screen on top of that same Stack.

### `features/products/screens/ProductDetailScreen.tsx`

Uses the same hooks pattern you just revised, and the cart store from Exercise 6.1 (Part 6) — until then, `add` is a safe no-op.

```tsx title="features/products/screens/ProductDetailScreen.tsx"
import { useEffect, useState } from 'react';
import { ActivityIndicator, Image, ScrollView, Text } from 'react-native';
import { useLocalSearchParams, router } from 'expo-router';
import { getProduct } from '../api';
import { Product } from '../types';
import { useCartStore } from '@/features/cart/store';
import { Button } from '@/shared/components/Button';
import { colors } from '@/shared/theme';

export default function ProductDetailScreen() {
  const { id } = useLocalSearchParams<{ id: string }>();
  const [product, setProduct] = useState<Product | null>(null);
  const add = useCartStore((s) => s.add);

  useEffect(() => {
    getProduct(Number(id)).then(setProduct);
  }, [id]);

  if (!product) return <ActivityIndicator className="flex-1" size="large" color={colors.primary} />;

  return (
    <ScrollView className="bg-bg" contentContainerClassName="gap-3 p-4">
      <Image source={{ uri: product.image }} className="h-64 w-full" resizeMode="contain" />
      <Text className="text-xl font-bold text-text">{product.title}</Text>
      <Text className="text-2xl font-extrabold text-primary">${product.price.toFixed(2)}</Text>
      <Text className="leading-5 text-muted">{product.description}</Text>
      <Button
        title="Add to cart"
        onPress={() => {
          add(product);
          router.back();
        }}
      />
    </ScrollView>
  );
}
```

### `features/cart/screens/CartScreen.tsx`

```tsx title="features/cart/screens/CartScreen.tsx"
import { FlatList, Text, View } from 'react-native';
import { useCartStore } from '../store';
import { CartItem } from '../components/CartItem';
import { Button } from '@/shared/components/Button';

export default function CartScreen() {
  const items = useCartStore((s) => s.items);
  const inc = useCartStore((s) => s.inc);
  const dec = useCartStore((s) => s.dec);
  const remove = useCartStore((s) => s.remove);
  const clear = useCartStore((s) => s.clear);

  return (

        data={items}

      />

        <View className="gap-2.5 border-t border-border pt-3">
          <Text className="text-lg font-extrabold text-text">Total: ${total.toFixed(2)}</Text>
          <Button title="Clear cart" variant="danger" onPress={clear} />

      )}
```

<Part n="6" title="State management, explained" time="2 hours" />

Every screen so far has used `useState` — memory that belongs to **one component**. The cart is different: the detail screen adds to it, the cart screen reads it, and the tab bar needs to show a badge count. Three unrelated screens, one shared piece of memory. This part explains *why* that needs a new tool, and *how* Zustand and Redux Toolkit each solve it — slowly, with live demos you can click before you touch real code.

### Zustand, from zero

A Zustand store is one function, `create()`, that returns a hook. Call that hook inside any component, anywhere, and you're reading (or changing) the **same** shared state — no wrapper component needed around your app.

<Explain parts={[
  ['create(', 'makes the store — runs once, when the module first loads'],
  ['(set) =>', 'the only function allowed to change state'],
  ['({ items: [], add: ... })', 'the initial state, plus every action, in one object'],
]} />

The live demo below is not a video or a canned animation — the exact `create((set) => ({ ... }))` code shown is running in your browser right now. Click the buttons and watch the same `add()`/`remove()` functions execute for real.

<ZustandLiveDemo />

**Try this, in order**, before writing any real code:
1. Add "Sneakers" twice. Notice the quantity goes to 2, not two separate rows — that's the `found ? ... : ...` branch in `add()`.
2. Open your browser's dev tools, add a `console.log(s)` inside `set((s) => {...})` in your mind — every click re-runs that whole function from scratch with the *previous* state as `s`.
3. Click `clear()`. The whole store resets to `{ items: [] }` in one call — no loop, no per-item removal.

> [!TIP]
> The one rule that breaks more carts than anything else: **always return a new array/object** from `set`. `s.items.push(x)` mutates the old array in place — React never notices, so the screen never repaints. `[...s.items, x]` makes a new array, which is why `add()` above is written that way.

### Redux Toolkit, from zero

Redux never lets a component change state directly. Instead it describes the change as a plain object — an **action** — and hands it to `dispatch()`. A **reducer** function receives the current state plus that action and calculates the next state. Nothing else is allowed to change it.

  ['add(product)', 'an action **creator**: a plain function that returns { type: "add", payload: product }'],
  [')', 'the reducer runs, a new state comes out, every subscribed screen re-renders'],
]} />

> [!NOTE]
> Redux Toolkit's `createSlice` uses a library called Immer internally, which is why `state.items.push(...)` is *safe* inside a slice reducer (but still forbidden everywhere else, including Zustand) — Immer intercepts that "mutation" and builds a new object behind the scenes. The reducer above writes it the plain, pre-Immer way so you can see exactly what happens underneath.

### Build the Redux Toolkit version (guided)

Keep Zustand working — Redux is added as a *parallel* implementation, so you can compare them side by side in your real app, not just the demo above.

```ts title="features/cart/cartSlice.ts"
import { createSlice, PayloadAction } from '@reduxjs/toolkit';
import { Product } from '@/features/products/types';
import { CartItemType } from './store';

type CartState = { items: CartItemType[] };
const initialState: CartState = { items: [] };

const cartSlice = createSlice({
  name: 'cart',
  initialState,
  reducers: {
    add(state, action: PayloadAction<Product>) {
      const found = state.items.find((i) => i.product.id === action.payload.id);
      if (found) found.qty += 1; // Immer lets us "mutate" safely
      else state.items.push({ product: action.payload, qty: 1 });
    },
    inc(state, action: PayloadAction<number>) {
      const found = state.items.find((i) => i.product.id === action.payload);
      if (found) found.qty += 1;
    },
    dec(state, action: PayloadAction<number>) {
      const found = state.items.find((i) => i.product.id === action.payload);
      if (!found) return;
      if (found.qty === 1) state.items = state.items.filter((i) => i.product.id !== action.payload);
      else found.qty -= 1;
    },
    remove(state, action: PayloadAction<number>) {
      state.items = state.items.filter((i) => i.product.id !== action.payload);
    },
    clear(state) {
      state.items = [];
    },
  },
});

export const { add, inc, dec, remove, clear } = cartSlice.actions;
export default cartSlice.reducer;
```

| | Zustand | Redux Toolkit |
| --- | --- | --- |
| Setup | 1 file, no Provider | slice + store + Provider + typed hooks |
| Update state | call a function | `dispatch(action)` |
| Boilerplate | very low | moderate (much less than old Redux) |
| DevTools / middleware | available | excellent, built in |
| Best for | small/medium apps, quick features | large apps, big teams, strict structure |
