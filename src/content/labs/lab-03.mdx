### Tokens, primitives and feature components

Split every screen into **layout**, reusable **UI primitives** (`components/ui`) and data-aware **feature components** (`features/<name>/components`). Keep colours, spacing and radius in one place:

```ts title="src/theme/tokens.ts"
export const colors = {
  background: '#0B1020', surface: '#151C31', text: '#F8FAFC',
  muted: '#94A3B8', primary: '#7CFFB2', danger: '#FB7185',
} as const;
export const spacing = { xs: 4, sm: 8, md: 16, lg: 24, xl: 32 } as const;
export const radius = { sm: 8, md: 14, pill: 999 } as const;
```

A primitive owns its **look, feedback, state and accessibility**; the feature only decides what happens on press. Prefer one `variant` prop over many booleans, and keep business data out of `ui/`.

### Relative paths vs the `@/` alias

An import path tells Metro **where the file is**. There are two ways to write it — like giving someone directions vs giving them an address:

> **Directions (relative):** “From my room, go out, down one floor, the kitchen is on the left.” Works only if you start in my room.
>
> **Address (alias):** “12 Nile Street, flat 4.” Works from anywhere.

Here are both ways to the **same file**. Folders are drawn as boxes inside boxes: `..` steps **out** of a box, `@/` **jumps** to `src/`, and each name steps **into** a box. Press **Play all**, then switch to `@/`:

<ImportJourney />

<Cards cols={3} items={[

  { icon: 'target', title: 'Alias: @/', text: 'An address **from `src/`**, the same from every file: `@/components/ui/AppButton`. Moving the importing file changes nothing.' },
  { icon: 'check', title: 'The rule', text: 'Inside one feature → `./` or `../`. Across boundaries (shared UI, theme, services) → `@/`.' },

<Demo id="imports" />

`@/` is not built in — you define it once in `tsconfig.json`. `"@/*": ["src/*"]` means: replace `@/` with `src/`. Expo’s bundler reads the same setting, so TypeScript and the running app agree.

```json title="tsconfig.json"
{
  "extends": "expo/tsconfig.base",
  "compilerOptions": {
    "strict": true,
    "baseUrl": ".",
    "paths": { "@/*": ["src/*"] }
  }
}
```

### Tabs for the main areas

A tab navigator draws one button per `Tab.Screen`. `screenOptions` can be a **function of the route**, so one line gives every tab its own icon. The navigator passes `color` (green when active) and `size`:

```tsx
<Tab.Navigator screenOptions={({ route }) => ({
  tabBarIcon: ({ color, size }) => <Ionicons name={ICONS[route.name]} color={color} size={size} />,
})}>
```

### Nesting: tabs inside a stack

A common root is `Stack(Auth, MainTabs, Details)`: the tabs live **inside** one stack screen. A `navigate()` call is offered to the screen’s own navigator first, then **bubbles up** to its parents. Pick a call and watch who handles it:

<NestedNav />

Type the nested navigator with `NavigatorScreenParams`, and nest as little as possible — every navigator adds history and options.

```ts title="src/app/navigation/types.ts"
import type { NavigatorScreenParams } from '@react-navigation/native';

export type MainTabParamList = { Feed: undefined; Profile: { userId: string } };
export type RootStackParamList = {
  Main: NavigatorScreenParams<MainTabParamList>;
  Details: { itemId: string };
};

// navigation.navigate('Main', { screen: 'Profile', params: { userId: '42' } });
```

### Public values with `EXPO_PUBLIC_`

Expo inlines every `EXPO_PUBLIC_` variable into the app. Use them only for public values such as the API address and the environment name.

```bash title=".env.development · .env.staging · .env.production"
# development
EXPO_PUBLIC_APP_ENV=development
EXPO_PUBLIC_API_URL=http://192.168.1.10:3000

# staging
EXPO_PUBLIC_APP_ENV=staging
EXPO_PUBLIC_API_URL=https://staging-api.example.com

# production
EXPO_PUBLIC_APP_ENV=production
EXPO_PUBLIC_API_URL=https://api.example.com
```

> [!CAUTION]
> **Never** put database passwords, service-role keys or private API secrets in a mobile app — `EXPO_PUBLIC_` means public. Commit `.env.example`; ignore the real `.env*` files. Keep secrets on a server.

### Give each build its own identity

An app variant sets the display name, the bundle identifier / package and the API environment, so all three builds can sit side by side on one phone.

```ts title="app.config.ts"
import type { ExpoConfig } from 'expo/config';

const variant = process.env.APP_VARIANT ?? 'development';
const production = variant === 'production';
const staging = variant === 'staging';

export default <ExpoConfig>{
  name: production ? 'Project' : staging ? 'Project (Staging)' : 'Project (Dev)',
  slug: 'project',
  ios: { bundleIdentifier: production ? 'com.team.project' : `com.team.project.${variant}` },
  android: { package: production ? 'com.team.project' : `com.team.project.${variant}` },
};
```

```json title="eas.json"
{
  "build": {
    "development": { "developmentClient": true, "distribution": "internal", "env": { "APP_VARIANT": "development" } },
    "staging": { "distribution": "internal", "env": { "APP_VARIANT": "staging" } },
    "production": { "autoIncrement": true, "env": { "APP_VARIANT": "production" } }
  }
}
```
